Kubernetes: Deploy, Configure, Troubleshoot

1. Deploy an application to Kubernetes

Developer → CI build and tests → container image → Amazon ECR → Kubernetes Deployment → Service → Ingress / Load Balancer → Users.

  1. Build and test the application; create a container image.
  2. Push the versioned image to a registry such as Amazon ECR.
  3. Define a Deployment with image, replica count, resource requests and limits, and probes.
  4. Apply manifests with kubectl apply -f k8s/.
  5. Verify rollout, pods, Service endpoints, and external routing.
  6. Use rolling updates and kubectl rollout undo deployment/my-app when needed.

Note: A Service is internal by default. External access requires appropriate networking and an Ingress controller or load balancer.

2. Production troubleshooting

Start with kubectl get pods -A and kubectl describe pod <pod> -n <namespace>; inspect events before changing resources.

  • Pending: scheduling constraints, CPU/memory requests, taints, PVCs, quotas.
  • CrashLoopBackOff: previous logs, startup command, configuration, dependencies and probes.
  • ImagePullBackOff: image name/tag, registry permissions, pull secrets and network access.
  • Running but unavailable: readiness, Service selectors, EndpointSlices, ports, Ingress and DNS.
  • High resource use: metrics, limits, HPA behavior, application profiling.
  • Node or network issues: node conditions, CNI, NetworkPolicy and DNS.

After remediation: fix → verify → monitor.

3. Kubernetes YAML anatomy

Common resource fields are apiVersion, kind, metadata, and spec. A Deployment's pod template is under spec.template.

apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app
spec:
  replicas: 3
  selector:
    matchLabels:
      app: my-app
  template:
    metadata:
      labels:
        app: my-app
    spec:
      containers:
        - name: web
          image: nginx:1.27
          ports:
            - containerPort: 80
          resources:
            requests:
              cpu: 250m
              memory: 256Mi
            limits:
              memory: 512Mi

Use namespace-scoped configuration, appropriate RBAC, Secrets for sensitive values, and Kustomize or Helm for environment-specific packaging. Never commit real secret values.

4. Example EKS repository layout

k8s-project/
├── .github/workflows/ci-cd.yml
├── app/
│   ├── src/
│   └── Dockerfile
├── k8s/
│   ├── namespace/
│   ├── deployment/
│   ├── service/
│   ├── ingress/
│   ├── config/
│   └── hpa/
├── terraform/
│   ├── modules/
│   │   ├── eks/
│   │   └── vpc/
│   ├── main.tf
│   ├── variables.tf
│   └── outputs.tf
└── README.md

Separate application build, infrastructure provisioning, and Kubernetes deployment into independently reviewed CI/CD stages. Do not automatically run destructive Terraform applies or cluster mutations from untrusted pull requests.
