DevOps & Cloud

CI/CD

From a code change to a reliable release: understand the practices that keep teams building, testing, and delivering together.

What is DevOps?

A culture and set of practices joining development and operations to deliver software frequently and reliably, with shared ownership.

What are the core practices?

Version control, continuous integration, automated testing, continuous delivery, infrastructure as code, observability, and fast feedback.

CI, delivery, or deployment?

Continuous integration
Merge and validate changes frequently with automated builds and tests.
Continuous delivery
Keep releases deployable, with approval before production.
Continuous deployment
Automatically release passing changes to production.

A typical delivery pipeline

Code → Build & test → Deploy to staging → Release to production

  1. Integrate. Push changes and open a pull request for review.
  2. Validate. Automatically run builds, tests, and code quality checks.
  3. Package. Create a versioned artifact that can be promoted across environments.
  4. Deliver. Deploy to staging, verify the release, and approve the production rollout, or automate it after checks pass.
  5. Monitor. Check application health after deployment and roll back if needed.

How to Build Your Own JARVIS Interface

How to Build Your Own JARVIS Interface

Build a voice-enabled personal AI agent in one weekend using nine practical steps. Give it a home, choose an agent framework and model, add your context and memory, then connect skills, tools, communication channels, and a custom interface.

Nine steps to your own JARVIS

  1. Give it a home. Use an old laptop, Mac Mini, or cloud server.
  2. Install an agent. Use a framework such as Hermes Agent to turn an AI model into a tool-using agent.
  3. Choose its model. Select Claude, Codex, Gemini, or another supported model based on your needs.
  4. Teach it your context. Explain who you are, what you do, and how your business works. Avoid sharing unnecessary sensitive information.
  5. Add persistent memory. Consider Honcho AI or another memory system to retain useful context across conversations, with controls to inspect and delete it.
  6. Give it skills. Add focused capabilities for the specific jobs you want it to handle.
  7. Connect your tools. Integrate email, calendars, documents, or a browser with least-privilege permissions and approval gates for consequential actions.
  8. Connect communication and voice. Explore Slack, Telegram, or iMessage integrations where supported. Add Hermes Voice and an ElevenLabs voice for spoken interaction.
  9. Build the JARVIS interface. Use a design tool such as Claude to create a custom dashboard, then connect it to your agent and voice interface.

Weekend goal: A working prototype that can converse, remember approved context, and use connected tools. Production-grade security, reliability, and integrations require additional work.

Production Deployment Explained

Production Deployment Explained

Here is how engineering teams take code from development to production. It all starts with a product manager creating user stories in Jira that explain what we're building and why — this is where requirements are defined. Engineers take those stories and start coding, commit changes to the GitHub repo, and merge them at the end of the sprint. CI pipelines such as Jenkins or GitLab CI build the application and run automated tests, while tools such as SonarQube analyze code quality and security. The code is packaged into Docker containers for consistent environments. QA tests in the dev environment to catch bugs, then features are deployed to staging/UAT for user acceptance testing. Finally, teams may use canary deployments for gradual rollout, feature flags to control feature exposure, and A/B testing to compare product variants while site reliability engineers monitor performance and respond to issues. The feature is now live for users — that’s generally how features reach your device.

Cloud Architecture & Infrastructure as Code

Scalable Cloud Microservices on AWS with Terraform

Explore an event-driven architecture for containerized batch processing and serverless microservices using AWS Batch on Fargate, AWS Lambda, AWS Step Functions, Amazon S3, and Terraform.

Reference architecture

Amazon S3 → AWS Lambda → AWS Step Functions → AWS Batch on Fargate → Amazon S3

An S3 event can invoke Lambda to validate a request and start a Step Functions workflow. The workflow coordinates processing steps and submits containerized, resource-intensive jobs to AWS Batch using Fargate. Results and processing artifacts are stored in S3.

Core components

  • Amazon S3: Store input files, outputs, and processing artifacts.
  • AWS Lambda: Handle lightweight event processing, validation, and workflow initiation.
  • AWS Step Functions: Orchestrate tasks, retries, timeouts, and failure handling.
  • AWS Batch on Fargate: Execute containerized batch workloads without managing EC2 hosts.
  • Terraform: Define and review infrastructure changes for storage, IAM, orchestration, compute, networking, and observability.

Engineering considerations

Design for idempotent processing, least-privilege IAM, encrypted storage, bounded retries, workflow visibility, cost controls, and appropriate Fargate resource limits. Use Terraform plan review and approval before applying infrastructure changes.
